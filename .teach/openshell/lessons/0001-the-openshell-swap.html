RHOAIENG-81030

odh does not become OpenShell. It hosts OpenShell.

One picture, then you can sort any task on this epic into “wire it in odh”, “fix it upstream”, or “still undecided”.

RHOAIENG-81030 is an integration epic. OpenShell already has a web UI and a Go BFF. odh-dashboard already knows how to load a plugin (same family as MLflow and model-registry). The epic is the adapter between those two facts — then it deletes the old adapter.

The old adapter is packages/agent-ops. It pretends Kubernetes Sandbox custom resources are the product API. OpenShell’s real product API is the gateway (workspaces, gateway auth, policies). After cutover, the Sandbox-CR UI, BFF, OpenAPI, and CR Cypress go away.

Two phone numbers

Same user-looking page (“list my sandboxes”). Completely different next hop. Flip between them.

Proven in this repo: packages/agent-ops/bff/README.md lists agents.x-k8s.io/v1beta1/sandboxes labeled openshell.ai/managed-by=openshell. The user’s kube token is forwarded; RBAC is Kubernetes verbs on that CR.

Upstream README: browser REST → Go BFF → gRPC (bearer) → gateway. The BFF relays a JWT; it does not validate it. ADR 0002 says federated mode uses the host’s auth proxy and the same x-forwarded-access-token header odh already forwards when authorize: true.

What “integration only” means in practice

If a sandbox list page looks wrong, that is usually an upstream bug. If the page never appears in the RHOAI nav, or API calls 404 at the host, that is usually an odh wiring bug.

odh is on the hook for:

  • A federated package that imports openshell-dashboard/pages (and api/types/slots) and registers host extensions (routes, nav, area flags).
  • Deploying the upstream Go BFF as the module container, with gateway URL/TLS env, plus Service / NetworkPolicy / proxy path.
  • An authenticated journey (list / create / delete in a workspace) without AUTH_DISABLED.
  • Flags: host area flag to hide the whole module; upstream flags (terminal) if the proxy cannot upgrade WebSockets.
  • At least one slot / extension-point path, documented.
  • Cypress + contract tests on the integrated path; then delete the Sandbox-CR stack.
  • Keep secrets write-only through the proxy — browser never sees credential values. That contract already exists upstream.

What the spikes already proved

Two parallel spikes sit under the epic. They are not the product launch; they shrink risk.

RHOAIENG-81066 — UI consume (Daniel Reed: spike complete)

  • odh can import upstream build:lib exports and render sandbox list + detail inside the host.
  • Thin adapter package (locally named packages/openshell so it would not collide with agent-ops). Later stories may reuse the agent-ops package name.
  • Host must wrap pages: TanStack Query v5 (module-local; host is still v4), AlertProvider, setApiBasePath('/_bff/openshell'), session-expired handler, onViewSandbox + controlled tabs. Upstream LoginPage is unused in federated mode.
  • React + PatternFly as MF singletons. Router was shared in the spike; v6 vs v7 is a recorded risk. Query is not shared.
  • After upstream PR #25, extra CSS workarounds were not needed.

RHOAIENG-81067 — BFF + gateway

Prove host proxy → upstream BFF → real gateway (OPENSHELL_GATEWAY_URL, TLS CA if needed). Preference on the ticket: ship the upstream BFF binary as the module Deployment, do not reimplement gateway clients in odh. Auth notes for the follow-on story: what token the gateway wants today vs what an odh session actually is.

The long Go “interface decoration + Chi” write-up is a future sharing pattern for the upstream BFF. It is not what makes 81030 done. Spike 81067 already prefers a binary in a container. We will cover decoration in a later lesson so you do not mix “run their binary” with “import their Go interfaces”.

Still open (do not pretend these are decided)

  • Auth bridge: shared OIDC issuer (upstream’s preferred standalone shape) vs token exchange vs something else. ADR 0002 even says: if token exchange happens, it belongs in the proxy/platform layer, not the BFF.
  • Packaging: confirm upstream BFF binary as the module image vs a thin odh-owned wrapper.
