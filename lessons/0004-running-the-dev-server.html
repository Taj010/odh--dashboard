Lesson 4: Running the Dev Server

Goal: Get the ODH Dashboard running on your machine, open it in the browser, and understand why the setup looks the way it does — so you can start making real UI changes.

The one-sentence version

Your laptop runs the React UI; an OpenShift cluster (that you log into with oc) supplies the real data.

This is not a self-contained toy app. The dashboard is a control panel for Kubernetes resources. Locally, you compile and hot-reload the UI. The API calls still need a real cluster (or a mock) to answer.

Primary source Read CONTRIBUTING.md — Running locally and docs/dev-setup.md. This lesson compresses those docs into a first-time path. When something fails, those pages are the source of truth.

1. What you need installed

ToolWhyCheck
Node.js ≥ 22 Runs the frontend build tooling node -v
npm ≥ 10 Installs packages; workspaces live at the repo root npm -v
oc (OpenShift CLI) Logs you into a cluster so the backend can talk to Kubernetes oc version

Go is listed in the README for packages with BFFs — you can skip Go for this lesson. Mission scope is frontend-first.

No cluster yet? You can still install deps and start the UI, but pages that fetch real data will fail or look empty until you complete oc login. Ask your team for shared-cluster access (see CONTRIBUTING's Shared Clusters link). This lesson still teaches the mental model.

2. Two ways to run — pick one

Path A — Frontend only usual

UI on your laptop. Talks to the cluster's backend. Best when you're only changing React/TS/PatternFly code.

cd frontend
oc login ...
npm run start:dev:ext

Path B — Frontend + local backend

Both processes on your laptop. Use when changing backend code, or when Path A isn't enough.

# from repo root
npm run dev

# or two terminals:
cd frontend && npm run start:dev
cd backend  && npm run start:dev

Either way, open: http://localhost:4010

URLWhat it is
http://localhost:4010Frontend (the dashboard you look at)
http://localhost:4000Local backend API (Path B only)
Your browser │ ▼ localhost:4010 ← React UI (webpack/rspack, hot reload) │ ▼ Backend API ←── Path A: cluster / Path B: localhost:4000 │ ▼ OpenShift / Kubernetes API (needs oc login)

3. Do this once (setup)

1

Install dependencies at the repo root

npm install

Because this is a monorepo, one install at the root wires up frontend/, backend/, and packages/. Don't only install inside frontend/ unless a doc tells you to.

2

Create .env.local

cp .env.local.example .env.local

This file is not committed. It holds cluster/project settings. At minimum, set OC_PROJECT (often opendatahub or redhat-ods-applications — ask your team which). Optionally fill OC_URL / credentials so make login works.

3

Log in to a cluster

From the OpenShift console: user menu → Copy login command, then paste into your terminal. Or:

make login
# or
npm run make:login

Confirm:

oc whoami
oc project

Tokens expire — you'll often re-login daily and restart the backend.

4. Start the app (today)

4

Start the frontend (recommended Path A)

cd frontend
npm run start:dev:ext

start:dev:ext sets EXT_CLUSTER=true so the UI talks to the external cluster backend. Wait until the terminal says the server is ready, then open http://localhost:4010.

5

Prove hot reload works

Pick a visible string in the UI (a page title works). Find it in the codebase (Cmd/Ctrl+Shift+F), change the text slightly, save. The browser should update without a full refresh. That loop — edit → save → see — is how you'll spend most days.

Win for this lesson Dashboard open at localhost:4010 + one tiny text change reflected in the browser. That's enough. Don't chase a perfect cluster setup in this session if access is blocked — get as far as you can and ask.

5. Mental model: why it's weird compared to a normal React app

  • Commands from the right folder — root for monorepo-wide tasks (npm install, npm run dev); frontend/ for UI-only scripts.
  • Auth is cluster auth — your oc session is how the backend impersonates/calls Kubernetes. No oc login → empty/errors.
  • Hot reload is the frontend only — change a .tsx file → instant. Change backend → restart that process.
  • Feature flags — append ?devFeatureFlags to the URL for a blue banner that toggles flags for your session only (dev-setup.md).

Key takeaways

  • 4010 = UI, 4000 = local backend
  • Path A (frontend + start:dev:ext) is the default for UI work
  • Root npm install — monorepo, not a single-package app
  • oc login connects your laptop to real cluster data
  • Hot reload = change TSX, save, watch the browser
