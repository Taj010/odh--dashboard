Lesson 5: Local Cluster Workflow

Goal: Understand what oc login actually does, how the dashboard talks to Kubernetes, and how to troubleshoot the most common "blank page" problems.

The one-sentence version

Your dashboard is a window into a Kubernetes cluster — oc login gives you a token that lets the dashboard read/write Kubernetes resources on your behalf.

1. What is a cluster?

Think of it like a remote server (or group of servers) that runs containers. Kubernetes manages those containers. OpenShift is Red Hat's distribution of Kubernetes with extras (like a web console, built-in auth, Routes for exposing apps).

Your laptop The cluster ───────── ─────────── browser → localhost:4010 OpenShift API (6443) │ │ dashboard backend ──────────→ reads/writes K8s resources │ (Projects, Pods, ConfigMaps, needs your token InferenceServices, Pipelines…) to impersonate you

The dashboard doesn't have its own database. Kubernetes IS the database. Every piece of data you see in the UI is a Kubernetes resource — a YAML object stored in the cluster.

2. The oc login flow

StepWhat happens
1. Get a tokenOpenShift console → user menu → Copy login command. You get a command like oc login --token=sha256~XXXXX --server=https://api.cluster.example.com:6443
2. Run itYour terminal now has a kubeconfig context with that token stored at ~/.kube/config
3. Backend reads itWhen the dashboard backend starts, it reads your kubeconfig to get the token and server URL
4. API calls use itEvery request from the UI → backend → cluster carries your token. The cluster checks your RBAC permissions.
Tokens expire! Shared clusters typically expire tokens after 12–24 hours. When pages start returning 401 errors or showing blank, your first instinct should be: re-login with oc login and restart the backend.

3. The .env.local file

This file lives at the repo root and is never committed (it's in .gitignore). It configures your local dev environment.

# .env.local — your personal config
OC_URL=https://api.mycluster.example.com:6443
OC_PROJECT=redhat-ods-applications
OC_USER=myuser
OC_PASS=mytoken
VariableWhat it does
OC_PROJECTThe namespace the dashboard watches. Usually opendatahub (ODH) or redhat-ods-applications (RHOAI).
OC_URLCluster API URL — so make login can auto-connect
OC_USER / OC_PASSCredentials for make login (optional if you paste the token command manually)

4. Useful oc commands for dashboard work

You don't need to master oc — but these are the commands you'll use weekly:

CommandWhat it does
oc whoamiShows your current username — quick check if you're logged in
oc projectShows current namespace
oc project redhat-ods-applicationsSwitch to a different namespace
oc get podsLists running containers in current namespace
oc get datascienceclustersCheck if RHOAI is installed
oc get odhdashboardconfig -o yamlSee the dashboard's own configuration CR
oc logs deploy/odh-dashboard -c odh-dashboardCheck dashboard backend logs on cluster
oc get routes -n redhat-ods-applicationsFind the URL where the dashboard is deployed on cluster

5. Troubleshooting the blank page

When you start the dev server and see nothing (or errors), check in this order:

  1. oc whoami — if it fails, token expired → re-login
  2. Is the backend running? — check terminal for errors
  3. Is OC_PROJECT correct? — wrong namespace = no dashboard config found
  4. Browser console (F12) — look for 401/403/404 network errors
  5. Feature flags — some pages require flags to be enabled (covered in the navigation lesson)
Most common fix 90% of "it was working yesterday" problems: oc login --token=... --server=... → restart backend → refresh browser.

6. Multiple clusters

You might switch between clusters (e.g., a shared dev cluster and a staging cluster). oc stores multiple contexts in ~/.kube/config.

# See all contexts
oc config get-contexts

# Switch to a different cluster
oc config use-context admin/api-staging-cluster:6443/admin

# Or just login again — it switches for you
oc login --token=... --server=https://api.staging.example.com:6443
Pro tip After switching clusters, restart the dashboard backend so it picks up the new kubeconfig context.

Key takeaways

  • Kubernetes IS the database — the dashboard reads/writes K8s resources, nothing else
  • oc login gives your backend a token to act on your behalf
  • Tokens expire — re-login is your #1 troubleshooting step
  • .env.local tells the dev server which cluster and namespace to target
  • oc whoami is the quick sanity check
