Lesson 12: Domain Deep-Dive

Goal: Understand the core domain concepts of OpenShift AI — what users actually do with this dashboard and what each major feature area represents.

The one-sentence version

This dashboard manages the full ML lifecycle: from organizing work (Projects) to developing models (Workbenches) to training them (Pipelines) to serving them in production (Model Serving).

2. Core domain concepts

Projects

What it is: A container for all your ML work. Technically a Kubernetes Namespace with special labels.

Contains: Workbenches, pipelines, data connections, model servers — everything for one initiative.

Code: frontend/src/pages/projects/ + concepts/projects/

Workbenches

What it is: A Jupyter Notebook or VS Code environment running in a container on the cluster.

K8s resource: A Notebook Custom Resource (from Kubeflow)

Users do: Write Python code, explore data, prototype models

Code: frontend/src/pages/projects/notebook/

Pipelines

What it is: Automated ML workflows — sequences of steps (data prep → train → evaluate → deploy).

K8s resource: Uses Kubeflow Pipelines (KFP) resources

Users do: Create pipeline definitions, trigger runs, view results

Code: frontend/src/concepts/pipelines/ + pages/pipelines/

Model Serving

What it is: Deploying a trained model as an API endpoint so applications can send it data and get predictions.

K8s resources: InferenceService, ServingRuntime

Users do: Deploy models, configure scaling, monitor performance

Code: frontend/src/pages/modelServing/ + concepts/modelServing/

Model Registry

What it is: A catalog of trained models with versions, metadata, and lineage.

Users do: Register models, track versions, find models to deploy

Code: packages/model-registry/

Data Connections

What it is: Credentials and endpoints for external data stores (S3 buckets, databases).

K8s resource: Secrets with specific labels

Users do: Connect workbenches and pipelines to data

Code: frontend/src/concepts/connectionTypes/

Key takeaways

  • Projects = Namespaces that organize all ML work
  • Workbenches = Jupyter/VS Code environments on the cluster
  • Pipelines = Automated ML workflows (train, evaluate, deploy)
  • Model Serving = Deploy models as API endpoints
  • Everything is a K8s resource — the dashboard is just a nice UI on top
  • Admin features (hardware profiles, serving runtimes) configure what users can access
