Dependency map (reference)

The One-Sentence Version

Epic 2 builds the product in the upstream repo; Epic 1 wraps that product inside odh-dashboard. You work in Epic 1. Epic 2 is your supplier — you import their pages and call their API shapes through a thin host adapter.

How a Page Load Works

When a user opens OpenShell workspaces in the RHOAI dashboard, data flows through four layers. You own layers 1 and 2; Epic 2 owns 3 and 4.

Browser (React in odh shell) │ │ fetch("/openshell/api/v1/workspaces") ▼ Host proxy (odh-dashboard) ← Epic 1: 89723 proxy config │ │ rewrite → sidecar :8943 ▼ OpenShell BFF sidecar (Go) ← Epic 1: 89726 image; Epic 2: BFF code │ │ Go OpenShell SDK (gRPC) ▼ OpenShell gateway (cluster) ← RHAISTRAT-1752 (not shipped in RHOAI yet)

The UI pages themselves are not written from scratch in odh-dashboard. Spike 81066 proved you import upstream exports:

  • ./pages — workspace list, sandbox detail
  • ./components, ./api, ./types, ./slots

Your job is the wrapper: providers, routing, setApiBasePath('/openshell/api'), navigation callbacks, feature flags.

Epic 2 — What You Need to Know (Not Build)

Contract, not implementation. You need to know what JSON comes back and what providers upstream pages expect. You do not need to read Go SDK code.

Upstream coupling (from spike 81066)

Upstream pages may still import standalone-app internals (authStore, AlertContext, role hooks). Your host wrapper must supply replacements until upstream decouples. File upstream follow-ups when you hit these — that is Derek's Epic 2, not your blocker for 89723.

89723 vs agent-ops

Spike 81066 used a separate packages/openshell package so it would not interfere with existing agent-ops (Sandbox CR path, port 8843). Later tickets may merge into agent-ops, but the pattern is the same as mlflow:

  • Thin ODH adapter package
  • Upstream UI as npm dependency
  • Dedicated BFF sidecar port (8943 for OpenShell vs 8843 for agent-ops)

Both paths coexist per the parent epic — native Sandbox CR deploy (Tracks 1–2) and OpenShell gateway admin (Track 3).
