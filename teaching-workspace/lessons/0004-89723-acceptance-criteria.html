Section A — Navigation & Discoverability

AC: Feature flag ON → OpenShell nav entry visible

What it means: When openshell (or agreed flag) is enabled, user sees a way into OpenShell workspaces/sandboxes.

Files to touch:

  • packages/openshell/frontend/src/odh/extensions.ts — register app.area + tab or nav
  • frontend/src/concepts/areas/const.ts — map area → feature flag
  • packages/plugin-core/src/areas/types.ts — add SupportedArea enum value

Pattern (from agent-ops):

// extensions.ts — register the area + feature flag
{
  type: 'app.area',
  properties: {
    id: 'openshell',
    featureFlags: ['openshell'],
  },
},
{
  type: 'app.tab-route/tab',
  flags: { required: ['openshell'] },
  properties: {
    pageId: 'agents-tab-page',  // same Agents tab page as Deployments
    id: 'openshell-workspaces',
    title: 'Workspaces',       // or "OpenShell" — confirm with design
    component: () => import('./OpenShellWrapper'),
    group: '2_openshell',
  },
}

Verify: enable flag in dev → Agents section shows new tab. Disable flag → tab gone.

AC: Feature flag OFF → no OpenShell nav or accidental routes

What it means: Every OpenShell extension uses flags: { required: ['openshell'] }. No orphan routes without the flag.

Files: Same extensions.ts — every app.route and app.tab-route/tab entry must have the flag.

Verify: flag off → direct URL /ai-hub/agents/openshell/... should not render OpenShell (404 or redirect).

AC: Click nav → bookmarkable URL in dashboard shell

What it means: URL bar shows a stable path like /ai-hub/agents/openshell/workspaces (exact path TBD in PR — ticket says e.g. /.../openshell/workspaces).

Files:

  • extensions.ts — app.route with explicit path
  • OpenShellRoutes.tsx — internal React Router for list ↔ detail

Pattern: Host owns the outer route; your wrapper owns nested routes (list at workspaces, detail at workspaces/:id).

Verify: copy URL, paste in new tab → same page loads inside dashboard chrome.

Section D — API Proxy

AC: Local dev → browser calls /openshell/api/... on host origin

What it means: No hard-coded localhost:8943 in frontend code. API client uses relative paths; host proxy forwards to BFF.

Files:

  • packages/openshell/package.json — module-federation.proxy block
  • Upstream API init — setApiBasePath('/openshell') so fetches hit /openshell/api/...

Pattern (from agent-ops):

// packages/openshell/package.json
"module-federation": {
  "name": "openshell",
  "authorize": true,
  "proxy": [
    {
      "path": "/openshell/api",
      "pathRewrite": "/api"
    }
  ],
  "local": { "port": 9113 },
  "service": { "name": "odh-dashboard", "port": 8943 }
}

The dashboard backend reads every package's module-federation block and registers proxies automatically (backend/src/routes/module-federation.ts).

Verify: DevTools Network tab → requests go to https://localhost:4010/openshell/api/... (host), not an external origin.

AC: Health path registered; npm run validate:ports passes

What it means: Port 9113 (local dev) and 8943 (sidecar) must not collide with other modules. Proxy includes readyz if needed.

Files: packages/openshell/package.json only (for port validation in this ticket — cluster manifests are 89740).

Verify: run npm run validate:ports from repo root — no duplicate port errors.
