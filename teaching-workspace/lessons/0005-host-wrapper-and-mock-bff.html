Lesson 5: The Host Wrapper & Mock BFF

Goal: Understand the four layers of code that wrap upstream OpenShell pages inside odh-dashboard, and set up a mock BFF so data flows end-to-end in dev without a real gateway.

Glossary · File checklist

The Four Layers

When OpenShell renders inside the dashboard, four layers stack on top of each other — outermost first. Each one does one job.

Layer 1 — Extensions (discovery)

extensions.ts

Tells the host: "I exist, here's my feature flag, nav entry, and route."

The host calls this at build-time. No React renders here — only metadata objects.

Layer 2 — Wrapper (providers)

OpenShellWrapper.tsx

Wraps everything in the providers upstream pages need: QueryClient, ModularArch context, alerts, storage.

Think of it as the "environment setup" — like plugging in power and internet before you turn on a computer.

Layer 3 — Routes (navigation)

OpenShellRoutes.tsx

React Router <Routes> inside the wrapper. Maps URL paths to pages.

/ → workspace list, /:id → sandbox detail, * → redirect.

Layer 4 — Upstream pages (UI)

Imported from openshell-dashboard

The actual list and detail components. You don't write these — you import them and pass callbacks.

How They Stack (Code)

This is the call chain from host to pixels:

Host auto-discovers extensions.ts ↓ Host renders tab component → OpenShellWrapper ↓ wraps children in providers OpenShellRoutes ↓ matches URL Upstream WorkspaceListPage or SandboxDetailPage ↓ fetches /openshell/api/v1/workspaces Mock BFF returns JSON

Layer 1: extensions.ts

This is the entry point the host discovers. It's a plain array of metadata objects — no JSX, no hooks. Pattern copied from packages/agent-ops/frontend/src/odh/extensions.ts.

// packages/openshell/frontend/src/odh/extensions.ts

import type {
  AreaExtension,
  TabRouteTabExtension,
} from '@odh-dashboard/plugin-core/extension-points';

const OPENSHELL = 'openshell';
const AGENTS_TAB_PAGE = 'agents-tab-page';  // same page ID as agent-ops Deployments tab

const extensions: (AreaExtension | TabRouteTabExtension)[] = [
  // 1. Register the feature-flag area
  {
    type: 'app.area',
    properties: {
      id: OPENSHELL,
      featureFlags: ['openshell'],
    },
  },
  // 2. Add a tab under the Agents page
  {
    type: 'app.tab-route/tab',
    flags: { required: [OPENSHELL] },
    properties: {
      pageId: AGENTS_TAB_PAGE,
      id: 'openshell-workspaces',
      title: 'Workspaces',
      component: () => import('./OpenShellWrapper'),
      group: '2_openshell',
    },
  },
];

export default extensions;

Key detail: pageId: 'agents-tab-page' is defined in the host's navigation extensions. Agent-ops adds a "Deployments" tab to it; you add a "Workspaces" tab. Same parent page, separate tabs.

Layer 2: OpenShellWrapper.tsx — Providers

This is where you set up the environment that upstream pages expect. Think of each provider as an answer to a question the upstream code will ask:

ProviderQuestion it answersWhy OpenShell needs it
ModularArchContextProvider "What mode am I in? What's my API prefix?" Tells upstream URL_PREFIX = '/openshell' so all API calls hit /openshell/api/v1/...
QueryClientProvider "Where do I cache server data?" TanStack Query v5 — kept module-local (host uses v4)
BrowserStorageContextProvider "Where do I save user preferences?" Column widths, table settings, etc.
NotificationContextProvider "How do I show toast alerts?" Success/error banners for actions 
// packages/openshell/frontend/src/odh/OpenShellWrapper.tsx

import * as React from 'react';
import { QueryClientProvider, QueryClient } from '@tanstack/react-query';
import {
  BrowserStorageContextProvider,
  DeploymentMode,
  ModularArchConfig,
  ModularArchContextProvider,
  NotificationContextProvider,
} from 'mod-arch-core';
import OpenShellRoutes from './OpenShellRoutes';

const URL_PREFIX = '/openshell';

const modularArchConfig: ModularArchConfig = {
  deploymentMode: DeploymentMode.Federated,
  URL_PREFIX,
  BFF_API_VERSION: 'v1',
};

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      refetchOnWindowFocus: false,
      retry: 1,
      staleTime: 30_000,
    },
  },
});

const OpenShellWrapper: React.FC = () => (
  <ModularArchContextProvider config={modularArchConfig}>
    <BrowserStorageContextProvider>
      <NotificationContextProvider>
        <QueryClientProvider client={queryClient}>
          <OpenShellRoutes />
        </QueryClientProvider>
      </NotificationContextProvider>
    </BrowserStorageContextProvider>
  </ModularArchContextProvider>
);

export default OpenShellWrapper;

URL_PREFIX is the critical line. It makes every API call from upstream components start with /openshell/api/v1/.... The host proxy (configured in package.json) then forwards those to the BFF sidecar on port 8943.

Layer 3: OpenShellRoutes.tsx — Navigation

This is where URLs map to pages. Upstream provides the page components; you connect them to React Router.

// packages/openshell/frontend/src/odh/OpenShellRoutes.tsx

import * as React from 'react';
import { Navigate, Route, Routes } from 'react-router-dom';

// These imports come from upstream openshell-dashboard
// Exact export names depend on what upstream publishes
const WorkspaceListPage = React.lazy(
  () => import('openshell-dashboard/pages/WorkspaceListPage')
);
const SandboxDetailPage = React.lazy(
  () => import('openshell-dashboard/pages/SandboxDetailPage')
);

const OpenShellRoutes: React.FC = () => (
  <React.Suspense fallback={<div>Loading...</div>}>
    <Routes>
      <Route index element={<WorkspaceListPage />} />
      <Route path=":workspaceId" element={<SandboxDetailPage />} />
      <Route path="*" element={<Navigate to="." replace />} />
    </Routes>
  </React.Suspense>
);

export default OpenShellRoutes;

Note: The exact import paths (openshell-dashboard/pages/WorkspaceListPage) depend on what the upstream repo publishes. Check the spike branch and upstream package.json exports to get the real paths.

Callback: onViewSandbox

The spike (81066) documented that upstream list page expects an onViewSandbox callback for row clicks. You wire it to React Router's navigate:

import { useNavigate } from 'react-router-dom';

const OpenShellWorkspaceList: React.FC = () => {
  const navigate = useNavigate();
  return (
    <WorkspaceListPage
      onViewSandbox={(id: string) => navigate(id)}
    />
  );
};

Layer 4: Mock BFF — Making Data Flow

Without a mock, your pages will render empty or error because /openshell/api/v1/workspaces returns 404. You have three options for mocking:

OptionHowEffortBest for
A. Dev proxy intercept Rspack dev config intercept Low Quick iteration
B. Minimal Go BFF Copy BFF skeleton, return static JSON Medium Closer to prod; reusable for 89726
C. JSON fixture server npx json-server or serve with static files Low Zero Go setup

Option A: Dev Proxy Intercept (simplest)

In your local rspack dev config, add a middleware that intercepts /openshell/api/* and returns mock JSON:

// packages/openshell/frontend/config/rspack.dev.js  (excerpt)

devServer: {
  setupMiddlewares: (middlewares, devServer) => {
    devServer.app.get('/openshell/api/v1/workspaces', (req, res) => {
      res.json({
        data: {
          items: [
            {
              id: 'ws-001',
              name: 'dev-sandbox',
              status: 'Running',
              createdAt: '2026-08-15T10:00:00Z',
            },
            {
              id: 'ws-002',
              name: 'staging-sandbox',
              status: 'Stopped',
              createdAt: '2026-08-20T14:30:00Z',
            },
          ],
        },
      });
    });

    devServer.app.get('/openshell/api/v1/workspaces/:id', (req, res) => {
      res.json({
        data: {
          id: req.params.id,
          name: `sandbox-${req.params.id}`,
          status: 'Running',
          createdAt: '2026-08-15T10:00:00Z',
          // Add whatever fields upstream detail page expects
        },
      });
    });

    return middlewares;
  },
}

Why this works: The frontend calls /openshell/api/v1/workspaces. In dev, rspack intercepts it before it tries to reach a real sidecar. You return hardcoded JSON that matches the expected shape.

Option B: Minimal Go BFF Stub

Copy the agent-ops BFF skeleton (packages/agent-ops/bff/) and strip it to a single healthcheck + workspace list handler. Add to your Makefile:

# packages/openshell/Makefile
dev-bff:
    cd bff && go run ./cmd/main.go \
      --port=4022 \
      --mock-k8s-client \
      --deployment-mode=standalone

This creates a real Go process returning mock data — useful if you want to test the proxy chain end-to-end locally.

Mock JSON Shape

Until Epic 2 story 87985 (API spec) lands, use the shapes from the spike and upstream code. A safe starting point:

{
  "data": {
    "items": [
      {
        "id": "ws-001",
        "name": "my-workspace",
        "status": "Running",
        "createdAt": "2026-08-15T10:00:00Z",
        "sandboxCount": 3
      }
    ]
  }
}

When 87985 delivers the real OpenAPI spec, update your mocks to match. For now, match whatever the upstream list component renders (check its TypeScript types).

The Full Data Flow (dev mode)

1. Browser renders OpenShellWrapper ↓ 2. Upstream WorkspaceListPage calls useQuery('/openshell/api/v1/workspaces') ↓ 3. Browser sends GET /openshell/api/v1/workspaces ↓ 4a. [Option A] rspack dev middleware intercepts → returns mock JSON 4b. [Option B] host proxy → Go BFF on :4022 → returns mock JSON ↓ 5. React Query caches response → upstream component renders table

Common Mistakes to Avoid

MistakeWhy it breaksFix
Hardcoding localhost:8943 in fetch Works in dev, fails in production (CORS, wrong host) Use URL_PREFIX + proxy; let the host rewrite
Sharing QueryClient with host Host uses TanStack v4, OpenShell uses v5 — runtime crash Keep QueryClient module-local
Missing feature flag on a route Route accessible even when OpenShell is disabled Every extension entry needs flags: { required: ['openshell'] }
Using window.location for navigation Full page reload, breaks dashboard shell Use React Router navigate()
No React.Suspense around lazy imports Blank screen while chunk loads Wrap lazy components in <Suspense fallback={...}>

Quiz

1. What does URL_PREFIX = '/openshell' control?

  • The filesystem path where files are saved
  • The API path prefix for all BFF requests
  • The Kubernetes namespace to deploy into
  • The npm package name of the module

2. Why is QueryClient kept module-local instead of shared with the host?

  • Sharing is too slow for performance
  • The host doesn't use React Query at all
  • Host uses TanStack Query v4; module uses v5
  • Kubernetes doesn't allow shared clients

3. What is the simplest way to get mock data flowing in dev for 89723?

  • Rspack dev middleware returning static JSON
  • Deploying a real OpenShell gateway locally
  • Waiting for Epic 2 to finish the Go BFF
  • Hardcoding workspace data in React state

4. What happens if you forget flags: { required: ['openshell'] } on a route?

  • The route shows a feature-flag error page
  • The build fails with a lint error
  • The host ignores the route entirely
  • The route is visible even when OpenShell is off
