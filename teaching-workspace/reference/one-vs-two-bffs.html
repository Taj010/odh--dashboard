Three questions (never merge them)

QuestionStatusAnswer
Two backends? Locked Yes. CR path = K8s Sandbox CRs. Gateway path = OpenShell gRPC.
Two processes? Current plan / undecided later Today: agent-ops :8843 + OpenShell :8943. Could merge later by importing the module.
Two codebases? Proposal Don’t fork. Import upstream; decorate or add routes.

Two paths

CR (Tracks 1–2) /agent-ops/api → agent-ops BFF :8843 → Sandbox CRs Gateway (Track 3) /_bff/openshell/api → OpenShell BFF :8943 → Gateway gRPC

Spike 81067: do not rewrite the OpenShell BFF in ODH. Ship / import it.

Embedding (one picture)

type Service struct {
    upstreamservices.SandboxService // Get/List/Delete promoted
}

func (s *Service) CreateSandbox(...) (*Sandbox, error) {
    sb, err := s.SandboxService.CreateSandbox(...) // delegate
    // ODH-only tweak
    return sb, err
}

Handler still depends on the interface. Swap the decorated service in server.Services{Sandbox: decorated}. No handler rewrite.

What 89723 cares about

  • Two URL prefixes in the host, not how many containers.
  • Mocks in front of those prefixes.
  • Do not fold OpenShell workspace APIs into agent-ops “to have one BFF” unless an ADR says import-and-merge.
